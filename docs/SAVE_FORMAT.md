# Формат сохранений v1

Дата: 2026-11-16 · Реализация: `src/sim/persistence/`, `src/worker/worldStore.ts` · Тесты: `tests/unit/persistence.test.ts`, сквозной тест «сохранить → выйти → открыть» в `tests/e2e/smoke.spec.ts`

## Что сохраняется

Мир = **параметры создания** + **динамическое состояние**.

Статика (рельеф, гидрология, климатические нормы, почвы, залежи, провинции) **не записывается**: генератор побитно воспроизводит её из параметров мира (seed, размер, климат, длина сезона). При загрузке статика генерируется заново и сверяется с сохранённым хешем генерации (`geoHash`). Это даёт 4–5 МБ на мир M вместо ~40 МБ.

Когда в фазе 3 появится правка рельефа игроком, правки станут отдельной секцией поверх сгенерированной статики.

## Размещение (OPFS, каталог `worldbound/`)

```
worlds/<id>/manifest.0.json        два слота манифеста, пишутся по очереди
worlds/<id>/manifest.1.json        (поколение N → слот N mod 2)
worlds/<id>/core.g<N>.bin          секции поколения N
worlds/<id>/env.g<N>.bin
worlds/<id>/agents.g<N>.bin
```

## Атомарность

1. Секции нового поколения N+1 пишутся в новые файлы.
2. Манифест N+1 пишется в свободный слот; в нём — CRC-32 его собственного текста и CRC каждой секции.
3. Секции поколений старше N удаляются; поколение N остаётся резервом.

При загрузке выбирается манифест с наибольшим поколением, у которого сходятся CRC текста и всех секций. Сбой на любом шаге оставляет целым предыдущее поколение (проверено тестом с обрезанной секцией).

## Манифест (JSON)

| Поле | Значение |
|---|---|
| `format`, `formatVersion` | `worldbound-world`, 1 |
| `generation` | номер поколения |
| `id`, `name` | идентификатор каталога, имя мира |
| `config` | `{name, seed, size, daysPerSeason, climate}` |
| `createdAt`, `savedAt` | реальное время (ISO) |
| `tick` | игровой такт |
| `worldgenVersion`, `geoHash` | версия генератора и хеш статики |
| `stateHash` | хеш всего состояния — проверяется после загрузки |
| `sections` | `{id: {file, schema, bytes, crc}}` |
| `check` | CRC-32 текста манифеста без этого поля |

## Секция (двоичная)

Заголовок 32 байта, little-endian:

| Смещение | Поле |
|---|---|
| 0 | `WBSC` |
| 4 | версия формата, u16 |
| 6 | версия схемы секции, u16 |
| 8 | идентификатор, 8 байт ASCII |
| 16 | длина нагрузки, u32 |
| 20 | CRC-32 нагрузки, u32 |
| 24 | резерв |

Формат манифеста 2 (фаза 3): набор секций открыт — обязательны `core` и `env`, остальные при отсутствии восстанавливаются миграцией; хеш состояния после загрузки сверяется, только если миграций не было.

Нагрузка — поля с выравниванием по 8 байтам: число (f64) или массив (длина f64 + байты).

| Секция | Схема | Содержимое |
|---|---|---|
| `core` | 1 | такт, скорость |
| `env` | 1 | влага почвы, снег, индекс зелени, расход, сток, водный баланс, погодные ячейки, поля погоды по чанкам, учёт регулятора осадков, номер часового шага |
| `agents` | 1 | тестовые агенты фазы 0 (отладка): столбцы, счётчики, стек свободных слотов |
| `flora` | 2 | травяной ярус (слоты), опад (масса, питание, качество), запас питания, суточные накопители и средние, полог, банк семян трав, число древесных в ячейке, ведомость вещества, древесные (столбцы, стек свободных слотов). Схема 1 (этапы 1–2 фазы 3, две раскладки) мигрирует; без секции (сохранения фазы 2) — травяной ярус из индекса зелени |

## Совместимость

- Каждая секция версионируется отдельно; новая система добавляет свою секцию, старые миры открываются.
- Секция с неизвестной версией схемы отклоняется с понятным сообщением (миграции появятся с первым изменением схемы).
- **Смена генератора** (`WORLDGEN_VERSION`) делает старые миры неоткрываемыми: статика не совпадёт. Пока игроков нет, это допустимо; до выхода v0.1 нужно либо замораживать генератор, либо сохранять статику явно.
- Экспорт и импорт одним файлом, ротация резервных копий — фаза 4 (`DEVELOPMENT_PLAN.md`).

## Автосохранение

Раз в 2 минуты реального времени (если мир менялся), при сворачивании вкладки, при выходе в меню и перед созданием или открытием другого мира.

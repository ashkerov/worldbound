## 1. Исправлено

### 1.1. Пауза и скорость (`SimHost.Advance`)

**Было.**
- При переходе на скорость 0 накопленный долг тактов продолжал выполняться: после отставания — до 160 тактов, это 16 с игрового времени при ×8.
- Команда, пришедшая посреди кадра, применялась только на следующем такте.
- `WorldSnapshot.Speed` обновлялся, только если в кадре был такт: на паузе снимок показывал старую скорость.

**Стало** — темп тактов вынесен в ядро (`Worldbound.Sim/Core/TickPacer.cs`, без Unity). Временная модель не менялась: такт — 100 мс игрового времени, ×N — N·10 тактов в секунду, долг ограничен 2 с.
- Ожидающие команды применяются перед **каждым** тактом (граница такта). Пауза, пришедшая между тактами, останавливает мир до следующего такта.
- На паузе долг обнуляется. После возобновления накопленное до паузы время не догоняется.
- Смена скорости пересчитывает оставшийся долг в такты новой скорости: сохраняется реальное время, а не «восьмикратный остаток».
- `SimHost.SetSpeed` применяет команду сразу: хост вызывается между тактами. Снимок получает новую скорость и такт, даже если такта не было.
- Делегат часов создаётся один раз на хост — без выделений памяти в кадре.

**Регрессионные тесты** — .NET 6, редактор, сборка:
- `PacerCheck`:
  - пауза без долга, с частичным долгом (0,5 такта не переносится через паузу), с большим долгом после отставания (158 тактов → 0);
  - возобновление (×1 0,3 с → 3 такта; ×4 0,5 с → 20);
  - переключение ×1/×2/×4/×8/×4/×2/×1 за 1 с → 10/20/40/80/40/20/10 тактов;
  - смена ×8 → ×1 посреди долга (78 → 9,75);
  - запись команды в журнал на такте применения.
- `HostCheck`:
  - скорость в снимке до первого такта;
  - немедленная пауза с обнулением долга, 0 тактов за 3 с паузы;
  - команда из ядра без такта;
  - возобновление ×2;
  - `Dispose`.

### 1.2. Надёжность чтения WBSV

Структура файла не менялась. Читатель теперь проверяет:
- место под заголовок секции и её длину относительно остатка файла;
- повторяющиеся идентификаторы и неизвестные флаги;
- допустимые символы идентификатора;
- число секций и версию формата (0 и новее — отказ);
- длины массивов (отрицательные и больше остатка);
- лишние байты внутри секций и после них;
- согласованность размеров статики;
- значения перечислений и диапазоны конфигурации.

Распаковка ограничена 1 ГБ, повреждённый поток Deflate — понятная ошибка. Любая ошибка разбора — `SaveException` для этого файла, после чего пробуются резервные копии.

**Тест `SaveRobustness`** — 23 испорченных файла, собранных из настоящего сохранения с пересчитанными CRC, чтобы ошибка доходила до разбора секций.

Все 22 некорректных варианта дают контролируемую `SaveException` с понятной причиной:

| Группа | Варианты |
|---|---|
| Длины секций | длина больше, огромная, меньше настоящей; число секций огромное, на одну больше |
| Идентификаторы и флаги | повторяющийся идентификатор, неизвестный флаг, недопустимые символы |
| Целостность | CRC секции; обрезанный, пустой, случайный файл; один изменённый байт |
| Версия и состав | новая и нулевая версия формата, нет секции |
| Содержимое секций | битый Deflate, отрицательная и огромная длина массива, лишние байты в секции, мусор в конфигурации |

Неизвестная секция `ZZZZ` загружается (совместимость вперёд). Испорченный основной файл → берётся `.bak1` с предупреждением.

### 1.4. Финальные исправления: версии схем секций

Раньше версия схемы секции считывалась, но не проверялась. Теперь у каждой **известной** секции (`CONF`, `GEOG`, `TIME`, `WTHR`, `WATR`, `FLIN`, `HASH`) задан поддерживаемый диапазон версий (`SaveFile.SectionVersions`, сейчас 1–1):
- версия 0 — некорректна;
- версия новее поддерживаемой — файл записан более новой программой;
- в обоих случаях — контролируемый отказ файла и переход к резервной копии.

Неизвестные секции пропускаются при любой версии. Формат файла не менялся.

Тесты в `SaveRobustness` (стало 27 испорченных вариантов и 2 проверки резервной копии):
- версия 0 у `TIME`;
- будущая версия 2 у `WATR` и 65535 у `GEOG`;
- неизвестные секции `FLOR` (версия 0, сжатая) и `Z9Z9` (версия 65535) — файл загружается;
- основной файл с будущей версией `WTHR` → берётся `.bak1`, причина записана в предупреждение.

## 3. Оставшиеся ограничения

1. Флора и фауна не перенесены. Покров `greenness` постоянен (0,25), поэтому обратной связи «растительность → испарение» в C# нет. Как её восстановить — `UNITY_MIGRATION_STAGE2_PLAN.md`, раздел 10.
2. Кадр с часовым шагом мира M длиннее остальных (до ~30 мс): шаг воды, заполнение полей снимка в Mono, загрузка текстуры.
3. Рельеф M — 1024 чанка без LOD; кадр ограничен видеокартой (~55 к/с без ограничения, 90–99 при ограничениях 90/120).
4. Такты ведёт главный поток. Отдельный поток — когда шаги перестанут помещаться в кадр (флора M, подготовка Wildlands).
5. Сохранение M — 27 МБ, в основном статика. Запись — 1,2–2,3 с в фоне.
6. Unity в batchmode требует запущенного Unity Hub (лицензия Personal).
7. Свёрнутый режим проверяется обычным запуском приложения. При запуске из bash через `timeout` окно один раз переключалось само (Stage 1, не повторилось).
8. Журнал команд в C# — только смена скорости; команд создателя ещё нет.

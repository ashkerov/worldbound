# Формат сохранений Windows-версии (WBSV) — Unity Migration Stage 1

Дата: 2026-11-21 · Ветка: `experiment/unity-windows-prototype` · Реализация: `unity/WorldboundProto/Assets/Worldbound/Sim/Persistence/SaveFile.cs` · Проверка: `Worldbound.Sim.Golden.SaveCheck` (редактор, сборка, `tools/simcli/run.sh save`)

Это **сохранение C#-состояния мира**, а не файл-заглушка `world.json` из оценки Unity: тот записывал только счётчик игровых часов и полным сохранением не был; в Stage 1 он удалён. В файл попадает всё, что сейчас есть в ядре C#. Флоры и фауны в ядре пока нет — их секций в файле нет, место под них зарезервировано (ниже).

## Чем отличается от формата TS (`docs/SAVE_FORMAT.md`)

| | TS (браузер, OPFS) | WBSV (Windows) |
|---|---|---|
| Статика мира | не хранится, генерируется заново и сверяется с `geoHash` | **хранится** (секция `GEOG`) и при загрузке сверяется с `geoHash`: сохранение не ломается при смене версии генератора |
| Контейнер | манифест JSON + файлы секций, два слота манифеста | один бинарный файл из секций |
| Атомарность | поколения файлов + слоты манифеста | временный файл → сброс на диск → `File.Replace` |
| Резерв | предыдущее поколение | 3 резервные копии `.bak1`–`.bak3` |

## Структура файла

```
"WBSV"                      4 байта
formatVersion               u32 (сейчас 1)
sectionCount                u32
секция × sectionCount:
  id                        4 ASCII
  version                   u16 — схема секции
  flags                     u16 — бит 0: данные сжаты Deflate
  length                    u64 — длина данных в файле
  crc32                     u32 — CRC-32 данных в файле
  data
crc32 всего файла           u32 — по всем предыдущим байтам
```

Числа — little-endian; массивы — `int32 длина` + сырые байты элементов (float32, float64, int32, int16, uint16, byte); строки — `BinaryWriter.Write(string)` (UTF-8 с префиксом длины). Десятичной записи чисел в файле нет: в Unity Mono разбор десятичных строк не всегда даёт тот же double (обнаружено golden-тестом, см. отчёт Stage 1).

## Секции версии 1

| id | Сжатие | Содержимое |
|---|---|---|
| `CONF` | нет | имя, seed, размер, климат, дней в сезоне, сценарий, изоляция |
| `GEOG` | да | вся статика генератора: n, размер ячейки, края, высоты, уклоны, уровни воды, расстояния до воды и моря, расход, нормы климата, почвы, плодородие, залежи, приёмники и порядок стока, озёра, провинции, ветер, рельеф 2 м, горизонт |
| `TIME` | нет | такт, скорость |
| `WTHR` | да | погодные ячейки, поля чанков (интенсивность, облачность, накопленные осадки), баланс регулятора |
| `WATR` | да | влага почвы, снег, покров (greenness), расход, сток, водный баланс, номер последнего часового шага |
| `FLIN` | да | накопители условий для растений (часть состояния флоры TS: accT, accW, accRunoff, accMinT, accHours, capillary) |
| `HASH` | нет | версия генератора, `geoHash`, хеш состояния среды на момент записи |

**Зарезервировано:** `FLOR` (флора: слоты трав, древесные, банк семян, подстилка, биомы, ведомость питания), `FAUN` (фауна), `EDIT` (правки рельефа создателем), `CMDS` (журнал команд). Читатель версии 1 пропускает неизвестные секции.

## Проверки при загрузке

1. Сигнатура и CRC всего файла.
2. CRC каждой секции; распаковка.
3. Версия формата: новее поддерживаемой — отказ с понятным сообщением; старее — цепочка миграций `k → k+1` (`SaveFile.Migrations`; в версии 1 миграций нет).
4. Обязательные секции на месте.
5. `hashGeo(статика из файла) == geoHash` из `HASH`; если версия генератора другая — предупреждение, статика берётся из файла.
6. После восстановления `EnvHash() ==` сохранённому хешу среды.

Если основной файл не прошёл любую проверку, по очереди пробуются `.bak1`, `.bak2`, `.bak3`; причина отказа основного файла попадает в предупреждения загрузки.

## Запись

1. `SaveFile.Take(sim)` — на потоке симуляции: копия изменяемого состояния в байты секций (статика неизменна и берётся по ссылке). Мир M: десятки миллисекунд.
2. `SaveFile.Write(capture, path)` — в фоновой задаче: сериализация статики, Deflate, CRC, запись `path.tmp` с `FileOptions.WriteThrough` и `Flush(true)`, сдвиг копий `.bak2 → .bak3`, `.bak1 → .bak2`, `File.Replace(tmp, path, path.bak1)`.

Размер: мир S — 6,9 МБ, мир M — 27,7 МБ (большая часть — статика `GEOG`: рельеф 2 м и горизонт). Запись M — 1,1–2,1 с в фоне, загрузка M — 0,5 с (замеры: `docs/unity-stage1/measurements/`).

## Проверено (`SaveCheck`)

- загрузка восстанавливает состояние побитно (хеш среды совпадает с сохранённым);
- 100 игровых часов после загрузки дают тот же хеш, что 100 часов непрерывного прогона;
- после записи нет `.tmp`, создаётся `.bak1`;
- испорченный байт в основном файле → загрузка берёт `.bak1` и сообщает причину.

## 1. Архитектура растительных систем

Три формы, как и задумано в `ARCHITECTURE.md` (разделы 6.1, 8.5):

| Форма | Представление | Почему |
|---|---|---|
| Травяной ярус (травы, цветы, мхи, кустарнички) | **Поле**: до 4 слотов видов на эко-ячейку 8 м (вид + биомасса) | 262 тыс. ячеек мира M × 4 — дёшево; индивиды трав не нужны |
| Кустарники | **Индивиды** в общем хранилище древесных | Нужны карточка, конкуренция за свет, расселение |
| Деревья | **Индивиды** в том же хранилище | Требование заказчика; 300 тыс. в мире M |

Общая схема суточного шага (выполняется по частям каждый игровой час — 1/24 ячеек и 1/24 деревьев за раз, каждая сущность ровно раз в сутки):

```
часовой шаг воды ──▶ суточные накопители ячейки: Σ температуры, Σ влаги, Σ света, градусо-дни
                                │
   ┌────────────────────────────┼─────────────────────────────┐
   ▼                            ▼                             ▼
травяной ярус               древесные (кусты, деревья)     разложение опада
рост ← T, влага, свет        рост ← T, влага, свет над       опад ─▶ питательные вещества
       под пологом, N              собой, N; фенология       (константа разлагателей)
конкуренция слотов           смертность, семена, расселение
расселение в соседей         опад листьев и древесины
   │                            │                             ▲
   └────────── опад, отмершая биомасса ───────────────────────┘
                                │
              полог по ячейкам (покрытие по высотным ярусам) ──▶ свет для трав и подроста
                                │
                 классификатор биома ячейки (производная, не хранится)
```

Правила, общие с остальной архитектурой: всё авторитетное — в воркере; случайность — счётчиковая (`seed, система, сущность, сутки`); порядок обхода фиксирован; камера и запросы в расчёте не участвуют.

## 2. Структуры данных

### 2.1. Ячейка (поля, `FloraState`)

| Поле | Тип | Единицы | Сохраняется |
|---|---|---|---|
| `slotSpecies[4n²]` | Uint8 | индекс вида, 255 — пусто | да |
| `slotBiomass[4n²]` | Float32 | г сухого вещества на м² | да |
| `litterFast[n²]` | Float32 | г/м² (листья, травы) | да |
| `litterWood[n²]` | Float32 | г/м² (древесина) | да |
| `nutrient[n²]` | Float32 | доступный запас, г/м² «элемента питания» | да |
| `canopy[4n²]` | Float32 | покрытие пологом по ярусам высоты (< 2, 2–6, 6–15, > 15 м) | нет — пересчитывается из древесных |
| `dayT, dayW, dayL, gdd` | Float32 | суточные накопители | да (часть суток до сохранения) |

### 2.2. Древесные (`WoodyStore`, SoA, ёмкость 600 тыс. для мира M)

| Столбец | Тип | Смысл |
|---|---|---|
| `x, z` | Float32 | положение, м |
| `species` | Uint8 | вид |
| `ageDays` | Float32 | возраст, игровые сутки |
| `biomass` | Float32 | кг сухого вещества (древесина + листва) |
| `leaf` | Float32 | облиственность 0..1 (фенология) |
| `health` | Float32 | 0..1 |
| `stage` | Uint8 | всход, подрост, взрослое, старое |
| `stressW, stressL` | Float32 | скользящие индексы водного и светового стресса |
| `generation, alive` | Uint8 | идентификатор с поколением (как у агентов) |

Производные (не хранятся, считаются из биомассы и вида): высота `H = Hmax·B/(B + B50)`, радиус кроны, площадь кроны, листовая масса. Карточка растения показывает их из симуляции.

Идентификатор — существующий формат `EntityKind.Tree` (4 бита типа + 8 поколения + 20 индекса) — до 1 048 575 слотов.

### 2.3. Учёт вещества (`FloraLedger`, Float64)

Сохраняемый в мире элемент — **абстрактный элемент питания** (аналог азота и фосфора вместе). Сухое вещество строится из CO₂ и воды (фотосинтез) и разлагается обратно — это открытый поток с явным учётом.

| Счётчик | Смысл |
|---|---|
| `N_soil + N_litter + N_plants` | Запасы элемента питания |
| `N_weathering` | Приход из почвообразующей породы (по плодородию почвы) |
| `N_fixation` | Фиксация бобовыми и ольхой |
| `N_leaching` | Вымывание со стоком (из водного шага) |
| `N_creator` | Внесено или убрано кистью создателя |
| `N_external` | Приход с семенами колонистов извне |
| `C_photosynthesis`, `C_respiration`, `C_decomposition` | Открытые потоки сухого вещества |

**Инвариант** (тест 3): `ΔN_запасов = N_weathering + N_fixation + N_creator + N_external − N_leaching` с относительной погрешностью ≤ 10⁻⁴ за 20 игровых лет (погрешность — округление Float32 в полях; ведомость — Float64). Рост биомассы невозможен без поглощения элемента питания в пропорции вида.

## 3. Схемы каталогов

Общий механизм: декларативная схема в коде (`src/sim/content/schema.ts`) — типы, диапазоны, перечисления, обязательность, ссылки между каталогами; проверка при загрузке в симуляции и командой `npm run check:content` в `verify`. Ошибка схемы — ошибка запуска с указанием файла, записи и поля. Почвы переводятся на этот же механизм.

### 3.1. `content/plants/plants.json` (вид)

| Группа | Поля |
|---|---|
| Общее | `id`, `name`, `form` (`herb`, `shrub`, `tree`), `leafHabit` (`deciduous`, `evergreen`, `annualDieback`) |
| Условия | `temperature {min, optMin, optMax, max}` (°C, среднесуточная), `frostKill` (°C), `moisture {min, opt, max}` (доля влагоёмкости), `shadeTolerance` (0..1), `nutrientDemand` (0..1), `soils` (предпочтения по типам почв) |
| Рост | `growthRate` (сутки⁻¹), `maxBiomass` (г/м² для трав; кг для древесных), `halfBiomass` (кг, для аллометрии), `maxHeight` (м), `maxCrownRadius` (м), `nutrientContent` (доля), `leafFraction` |
| Жизненный цикл | `maturityYears`, `lifespanYears`, `baseMortality` (год⁻¹) |
| Размножение | `seedMass` (г), `fecundity` (семян на м² кроны в год), `dispersal {mean, max}` (м), `seedSeason` (доля года), `establishment` (вероятность при подходящих условиях), `spreadRate` (для трав — доля биомассы в соседей за сутки) |
| Экосистема | `fixesNutrient` (г/м²/год), `litterQuality` (скорость разложения), `flammability` (на будущее — не используется до фазы 5, в схеме помечено) |
| Колонизация | `colonistWeight` (вероятность появления извне при пригодных условиях) |

Представление (форма кроны, цвета листвы по сезонам, тип модели) — отдельный каталог `content/presentation/plants.json`, чтобы баланс не зависел от графики (`ARCHITECTURE.md`, раздел 6.3).

### 3.2. `content/biomes/biomes.json` (биом)

`id`, `name`, `color`, `rule` — упорядоченные условия по фактическим величинам ячейки: покрытие пологом деревьев и кустов, биомасса трав, доля хвойных, среднегодовая температура, влага, тип воды. Первый совпавший биом — результат. Биом **не хранится**: вычисляется из состояния растительности и условий.

## 4. Взаимодействие систем

| Связь | Механизм |
|---|---|
| Вода → растения | Суточная средняя относительная влага почвы; водный стресс |
| Растения → вода | Транспирация в часовом шаге воды умножается на листовую поверхность ячейки (травы + полог) вместо нынешнего индекса зелени |
| Близость реки или озера → влага | **Новое**: подпитка влаги почвы ячеек в нескольких метрах от воды (капиллярный подъём), убывающая с расстоянием — основа прибрежной растительности (тест 4) |
| Температура, снег → фенология | Градусо-дни для распускания, порог похолодания для листопада, снег прекращает рост трав |
| Полог → свет | Покрытие кронами по ярусам; свет под пологом по закону Бера |
| Растения → почва | Опад, отмирание; разложение с константой разлагателей, зависящей от температуры и влаги |
| Почва → растения | Запас элемента питания ограничивает рост |
| Вода → вымывание | Часть запаса уходит со стоком ячейки |
| Рельеф (кисть) → гидрология → всё остальное | Пересчёт гидрологии целиком в воркере после правки (с задержкой), затем уклоны, расстояния до воды, тип воды |
| Растения → рендер | Снимок древесных по чанкам и текстуры трав, опада, полога; только данные |
| Растения → классификатор биома → слои | Производная |

Новые системы в планировщике (порядок фиксирован): погода → вода → **флора (часть суток)** → тестовые агенты.

## 5. Сохранения

| Секция | Схема | Содержимое |
|---|---|---|
| `core` | 1 | без изменений |
| `env` | 1 → **2** | плюс суточные накопители; миграция 1 → 2 заполняет их нулями |
| `agents` | 1 | без изменений |
| `flora` | **1, новая** | слоты трав, опад, запас питания, древесные, ведомость |
| `terrain` | **1, новая** | правки рельефа: список изменённых чанков с высотами 2 м и высотами ячеек |
| `creator` | **1, новая** | источники воды, слой влияния на влажность, история команд создателя (для воспроизводимости) |

Правила совместимости:

1. Набор секций манифеста становится открытым: загрузчик требует `core`, `env`; остальные необязательны и имеют миграцию «секции нет».
2. **Сохранение фазы 2** (нет `flora`, `terrain`, `creator`, `env` схемы 1): флора создаётся из сохранённого индекса зелени — травяной ярус подходящих местных видов с биомассой, пропорциональной зелени, без деревьев; рельеф без правок. Зафиксировано тестом на замороженном сохранении фазы 2 (`tests/fixtures/phase2-world/`).
3. **Правки рельефа**: после загрузки статика генерируется по `seed`, сверяется `geoHash` **исходной** генерации, затем применяется секция `terrain` и гидрология пересчитывается детерминированно. Хеш состояния после загрузки включает рельеф и гидрологию.
4. `WORLDGEN_VERSION` не меняется: начальная растительность — отдельный этап «заселения» после генерации, не входящий в `geoHash`.
5. Новые поля `WorldConfig`: `scenario` (`genesis` / `wild`) и `isolated` — со значениями по умолчанию для старых манифестов.

Ожидаемый объём: мир M — ~20 МБ без сжатия при 300 тыс. деревьев. Если превысит бюджет 30 МБ — сжатие fflate (MIT) для секции `flora`.

## 6. План производительности

| Бюджет (Iris Xe, мир M) | Цель | Как измеряется |
|---|---|---|
| Средний такт на ×1 | ≤ 6 мс | Статистика воркера |
| Худший такт | ≤ 40 мс (вода и флора разнесены по тактам) | Статистика воркера |
| Древесные: суточный шаг 300 тыс. | ≤ 150 мс на сутки (≤ 7 мс за часовую часть) | `npm run flora:bench` |
| Травы: суточный шаг 262 тыс. ячеек × 4 слота | ≤ 60 мс на сутки | то же |
| Кадр: облёт с 300 тыс. деревьев, средний пресет | ≥ 35 к/с, без кадров > 100 мс | `tests/headed/world-flyover.spec.ts` |
| Треугольники на среднем пресете | ≤ 1,0 млн | статистика рендера |
| Память воркера | ≤ 300 МБ | `performance.memory`, снимки кучи |
| Сохранение мира M | ≤ 30 МБ | размер секций |

Приёмы:

- **Симуляция**: суточный шаг частями по часам; столбцовые массивы; ни одного выделения памяти в шаге; полог по ячейкам вместо попарных расчётов; разнос часового шага воды на несколько тактов и предрасчёт весов интерполяции погоды.
- **Рендер деревьев**: инстансинг по (вид × LOD) — десятки вызовов отрисовки, а не сотни тысяч объектов; данные экземпляров — собственные атрибуты (позиция, размер, облиственность, сезонный цвет) вместо матриц 4 × 4. Уровни: вблизи (< 150 м) — процедурная модель с листовыми карточками (приёмы прототипа 1A), средний (< 700 м) — упрощённая, дальний (< 2,5 км) — импостор, дальше — цвет и шероховатость полога в материале рельефа.
- **Травы и цветы**: GPU-инстансы только вокруг камеры; плотность и состав — из текстуры слотов ячеек.
- **Передача данных**: снимок древесных по чанкам, только изменённые чанки; полный снимок — при загрузке и правках.

## 8. Риски и эксперименты

| Риск | Эксперимент или мера |
|---|---|
| Сукцессия не воспроизводится или вырождается (лес везде, либо ничего) | Стенд баланса на участках с заданными условиями; калибровка каталога; отчёт с рядами |
| 300 тыс. деревьев не укладываются в бюджет кадра на Iris Xe | Синтетический стенд рендера на этапе 5 до полировки моделей; при нехватке — сокращение дальности деталей, а не числа деревьев в симуляции |
| Выращивание мира «дикой природы» при создании долгое (годы симуляции) | Замер на этапе 4; варианты в разделе 9 |
| Пересчёт гидрологии после правки рельефа на мире M — сотни миллисекунд | Задержка применения, индикатор; ограничение частоты |
| Объём сохранения > 30 МБ | Сжатие секции `flora` |
| Сжатие года (20 суток) против долгой жизни деревьев | Параметры роста заданы «на игровой год»; сукцессия в десятки игровых лет видна только в стенде и (в фазе 4) в таймлапсе |

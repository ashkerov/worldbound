Каркас готов: симуляция, рендер и интерфейс разделены и общаются только по протоколу. Все четыре критерия выхода фазы выполнены и проверены автоматически.

| Критерий выхода (DEVELOPMENT_PLAN.md) | Результат | Чем проверено |

| Рельеф рисуется из данных воркера; тестовые агенты движутся плавно при 10 тактах/с | Выполнен | Сквозной тест: такты 10/с, положения агентов меняются между кадрами |
| Пауза и скорости ×1–×8 работают | Выполнен | Сквозной тест: замер частоты тактов на каждой скорости |
| Ядро симуляции запускается в Node без браузера | Выполнен | `npm run headless`, модульные тесты |
| Запрещённый импорт ломает сборку | Выполнен | `npm run check:boundaries` — 9 проверок |

## 4. Проверка WebGPU и WebGL 2

Оба пути проверены отдельно, одним и тем же набором из четырёх тестов. Отрисовка аппаратная (тест падает при программной).

| | WebGPU | WebGL 2 |
|---|---|---|
| Адаптер | Intel, gen-12lp (Iris Xe) | ANGLE, Intel Iris Xe, Direct3D 11 |
| Запуск, рельеф, движение агентов | Пройден | Пройден |
| Пауза и скорости | Пройден | Пройден |
| Команды и хранилище OPFS | Пройден | Пройден |
| Частота тактов ×1 / ×2 / ×4 / ×8, 1/с | 10,0 / 20,3 / 40,3 / 80,7 | 10,0 / 20,3 / 40,3 / 81,3 |

Нагрузочная проба: 8000 агентов (1,6 млн треугольников, 3 вызова отрисовки), окно 1280×720.

| | WebGPU ×1 | WebGPU ×8 | WebGL 2 ×1 | WebGL 2 ×8 |
|---|---|---|---|---|
| Кадров/с | 56 | 60 | 54 | 54 |
| Кадр, мс (средний / худший) | 17,8 / 22,7 | 16,7 / 17,8 | 18,5 / 21,4 | 18,6 / 21,8 |
| Такт, мс (средний / худший) | 2,40 / 2,70 | 2,40 / 3,20 | 3,38 / 4,40 | 3,16 / 6,10 |
| Тактов/с | 10,0 | 79,8 | 9,8 | 79,9 |
| Пропущено тактов | 0 | 0 | 0 | 0 |

Это проба каркаса, а не замер бюджетов игры: сцена примитивна, агенты не принимают решений. Бюджеты проверяются в фазе 1.

Наблюдение: такт в воркере браузера примерно в 4 раза медленнее, чем то же ядро в Node (2,4 мс против ~0,55 мс на 8000 агентов). Вероятные причины — воркер попадает на энергоэффективные ядра, а встроенная графика делит с процессором тепловой бюджет. Вывод для фазы 1: производительность симуляции нужно мерить в браузере одновременно с рендером, а не только в Node.

## 6. Нерешённые вопросы и известные ограничения

**Требуют решения заказчика**

1. **Целевая машина.** Доступная для замеров машина (i5-1235U, Iris Xe, 8 ГБ) слабее той, что названа целевой в архитектуре (GTX 1650). Нужно решить, какая из них основная цель. До решения все замеры относятся к эталону A.
2. **Коммиты.** Git-репозиторий создан, но ни одного коммита не сделано — жду указания.

**Ограничения каркаса**

3. Проверен только Chromium (Edge). Firefox и Safari не проверялись.
4. Детерминизм между браузером и Node подтверждён только для одного движка JS (V8 в обоих случаях). Межбраузерный детерминизм генерации мира проверим в фазе 2.
5. Частота кадров ограничена вертикальной синхронизацией: «60» означает «не ниже 60». Запас сверху не измерялся.
6. Замеры идут в безголовом режиме в окне 1280×720, а не 1920×1080.
7. Свёрнутая вкладка: браузер замедляет таймеры, симуляция при этом отстаёт. Компенсация (движок догоняния) запланирована на фазу 4.
8. Снимок кадра передаёт идентификатор как число одинарной точности, а таблица поиска в рендере рассчитана на 65 536 сущностей. Для фазы 0 достаточно; будет заменено при появлении фауны.
9. OPFS проверена самотестом (запись, чтение, перезапись, список, удаление). Формата сохранений, экспорта и резервных копий пока нет — фазы 2 и 4.
10. Камера — простая орбитальная. Стратегический и свободный режимы — фаза 2.

**Особенности окружения**

11. На этой машине петлевой адрес IPv6 (`::1`) недоступен из командной оболочки, поэтому серверы разработки и тестов привязаны к `127.0.0.1`.
12. Использован TypeScript 6.0.3, а не вышедший 7.0: линтер типов пока поддерживает версии до 6.0 включительно.
13. При установке npm предупреждает о неутверждённом установочном скрипте `esbuild`; на работу сборки и тестов это не повлияло.

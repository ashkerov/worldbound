# WORLDBOUND — Unity Stage 2.2: расписание флоры, почва, голая земля

Дата: 2026-11-22 · Ветка: `experiment/unity-windows-prototype` · Эталон TS: `7b2fbabbc189f33a3181c7dbc72e54cd3aa8a65b` · Результаты: `docs/unity-stage2-2/`

Флора встроена в расписание `Worldbound.Sim` с точным расписанием TS: 144 порции в сутки и тот же порядок. Перенесены:
- суточные средние и сброс накопителей воды;
- почва: выветривание, вымывание, разложение;
- живой покров — вход испарения;
- суточное обновление биомов.

**20 игровых лет** голой земли (Genesis, изоляция, S/42) совпадают с настоящим TS `Simulation.stateHash()` **побитно** после каждой из 144 порций первых суток и после каждых суток, в .NET 6, редакторе Unity (Mono) и сборке Windows (Mono; вода — Mono или Burst). Рост, размножение, прорастание, древесные, колонизация, семена региона, Wildlands, секция `FLOR`, Burst для флоры и визуализация не делались — по условию этапа.

## 2. Расписание

### 2.1. Порядок систем в такте (как планировщик TS)

| Система | Период | Фаза | Такты в часе (от начала часа) |
|---|---:|---:|---|
| Погода | 50 | 0 | 0, 50, 100, 150, 200, 250 |
| Вода | 300 | 0 | 0 |
| Флора | 50 | 25 | 25, 75, 125, 175, 225, 275 |

- В такте системы идут в порядке погода → вода → флора.
- Флора никогда не совпадает в одном такте с водой или погодой: фаза 25.
- Первая порция часа идёт после часового шага воды этого часа.
- 6 порций в час, 144 в сутки.

### 2.2. Порция флоры (`FloraSystem.Run`, такт t ≡ 25 mod 50)
1. `hour = ⌊t/300⌋`, `sub = ⌊(t − 300·hour)/50⌋`, `slice = hour mod 24`. Контекст суток:
   - `dt = 1/(4·dps)`, `yearFrac`;
   - `day = ⌊hour/24⌋`, `dayOfYear = day mod (4·dps)`;
   - площадь ячейки;
   - `holdDays = max(2, round(4·dps/4))`.
2. `slice = 0` и `sub = 0` (начало суток) → `Cover.Refresh(world, false)` — полог. Деревьев нет, поэтому покрытия нулевые.
3. Ячейки: строки `z ≡ slice (mod 24)`, столбцы `[⌊sub·n/6⌋, ⌊(sub+1)·n/6⌋)`, только суша → `ProcessCell`.
4. Древесные: индексы `i = slice + 24·sub + 144·k < highWater` (граница — на начало порции). Живое растение — это этап 2.4, шаг останавливается (раздел 2.3). Цикл и граница сохранены.
5. Край: если мир не изолирован или идёт подготовка, это колонизация — этап 2.5, шаг останавливается. Структура цикла сохранена.
6. `sub = 5` → `lastSliceHour = hour`.

### 2.3. Ячейка (`ProcessCell`) — порядок TS
1. `accHours > 0` → `dayT = accT/accHours`, `dayW = accW/accHours`. Читаются `T`, `W`, сток. Сброс: `accT = accW = accRunoff = 0`, `accMinT = 99`, `accHours = 0`.
2. **Травы, банк семян, прорастание, старение банка — этап 2.3.**
   - Без вида в слотах проходы TS не меняют ничего, кроме записи запаса питания тем же значением.
   - Вид в слоте или семена в банке (прорастание при ≥ 0,002 г/м², старение при > 0) → `FloraNotPortedException`.
3. **Почва** — коэффициенты из `system.ts`:
   - `weathering = (0,4 + 1,6·fertility)·dt`;
   - `leach = n·min(0,3, runoff/(capacity·3))`;
   - `decomp = clamp((T+3)/18, 0, 1,4) · smoothstep(0,05, 0,35, W) · (1 − 0,5·smoothstep(0,92, 1, W))`;
   - `kFast = min(0,9; 2,5·quality·decomp·dt)`, `kWood = min(0,9; 0,18·decomp·dt)`;
   - опад и его элемент питания уменьшаются, питание растёт;
   - ведомость: выветривание, вымывание, разложение.
4. `regionalSeedRain` → `FloraNotPortedException` (этап 2.5).
5. `env.greenness[c] = GreennessOf(c)` — **настоящий покров, вход следующего часового шага воды**.
6. `UpdateBiome`:
   - сглаживание (EMA, 3/год·dt) травы по сообществам, влаги и покрытий — только при `dayT > 8` и до осени (0,68 года);
   - классификация по каталогу;
   - запас порога (`ConfirmsChange`);
   - кандидат держится `holdDays` суток подряд → смена.

**Защита от молчаливого расхождения.** Перенесённая часть равна TS только в мире без растений, семян и притока. В любом другом мире TS пошёл бы в ещё не перенесённую ветвь, поэтому C# в той же точке бросает `FloraNotPortedException` с указанием этапа. `Simulation.FloraUnsupported` сообщает причину заранее:
- идёт подготовка Wildlands;
- мир не изолирован;
- есть древесные;
- есть травы;
- есть семена.

Приложение такой мир создаёт, но такты не ведёт и показывает причину. Проверки Stage 1 (сохранение, темп, хост, устойчивость WBSV) переведены на мир Genesis + изоляция: их цель — механизмы, а не сценарий.

### 2.4. Общие буферы `BiomeState`
Вход классификатора и буфер трав — общие для процесса, как модульные объекты TS. Поэтому `InitBiomes` и каждая порция флоры выполняются под блокировкой `BiomeState.Gate`:
- экземпляры `Simulation` могут жить в разных потоках, но их флора идёт строго последовательно;
- скрытого параллелизма нет;
- параллельный расчёт клеток (этап 2.7) потребует перенести буферы в состояние.

### 3.2. Баланс вещества
`nutrientStock − initialStock = nutrientBudget`:
- **наибольшая относительная ошибка за 20 лет — 1,44·10⁻⁹**, в конце — 1,12·10⁻⁹ (допуск 10⁻⁴);
- значения побитно равны TS каждые сутки.

Что происходит с почвой голой земли (модель TS, перенесена как есть):

| | Сутки 1 | Сутки 20 | Сутки 80 (4 года) | Сутки 200 (10 лет) | Сутки 400 (20 лет) |
|---|---|---|---|---|---|
| Запас питания, т | 14,47 | 7,94 | 4,29 | 3,52 | 3,64 |
| Выветривание (накоплено), т | 0,16 | 3,29 | 13,15 | 32,87 | 65,74 |
| Вымывание (накоплено), т | 0,55 | 10,20 | 23,71 | 44,21 | 76,95 |

Без растений, которые удерживают элемент питания, вымывание стоком сначала быстро уносит начальный запас. Примерно к 10-му году выветривание и вымывание уравновешиваются, и запас стабилизируется около 3,5–3,6 т.

**Ограничение проверки:** разложение у голой земли выполняется, но всегда на нулевом опаде. Его арифметика на ненулевом опаде будет проверена в этапе 2.3, когда опад дадут травы.

### 3.4. Чувствительность эталона
Проверено подменами в C# с последующим возвратом.

| Подмена | Результат |

## 7. Оставшиеся ограничения
1. **Перенесённая флора ведёт только голую землю** (Genesis + изоляция). Wildlands, открытый мир, миры с растениями или семенами создаются, но такты не идут: шаг остановится с `FloraNotPortedException`, приложение показывает причину. Снимается этапами 2.3–2.5.
2. **Разложение проверено только на нулевом опаде** (раздел 3.2).
3. **Сохранение не содержит флору** (`FLOR` — этап 2.6). После загрузки флора пустая: дневные средние и биомы начнут заново, ведомость — с нуля. Хеш среды после загрузки и продолжение совпадают, полный хеш — нет. Это известное ограничение до 2.6.
4. **Общие буферы `BiomeState`** — флора всех экземпляров `Simulation` идёт последовательно под блокировкой (раздел 2.4).
5. **Mono в 2,5 раза медленнее .NET 6** на порции голой земли. Burst для флоры — этап 2.7.
6. **Расписание проверено на сезоне 5 суток** (по умолчанию). Другие длины сезона проходят тот же код, но отдельного эталона G3 для них нет (эталон среды Stage 1 включает сезон 8 суток без флоры).
